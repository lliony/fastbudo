# 0.0.9 发布验证

变更见[变更日志](../../CHANGELOG.md)，构建与兼容边界见[项目说明](../../README.md)，导航见[文档索引](../README.md)。

## 发布范围

- 主应用与 Finder 扩展均为 0.0.9，构建号 9。
- 「版本更新」设置新增“自动下载更新”开关（默认关闭）：开启后启动时自动检查正式版，发现新版本不再询问，直接下载、安装并重启应用；归档任务进行中自动跳过，检查或安装失败静默留待下次启动重试。实现见[自动下载更新验证](2026-11-04-auto-download-update.md)。
- 压缩/解压任务改为后台静默执行，状态栏浮窗不再展示任务状态，也不再自动弹出任务窗口。

## 构建与自动验证

- 固定第三方引擎构建通过；19 项 Bridge 测试通过；154 项 App 测试（21 套）通过，含更新检查分类、下载限制、目录交换回滚与重启脚本恢复；1 项真实窗口生命周期测试通过。
- Apple Silicon Release 构建通过。主应用、Finder 扩展、7zz、7z.so 和 ArchiveBridge 均为 arm64，最低 macOS 27.0。
- Intel Release 交叉编译通过（`ARCHS=x86_64`、`MACOSX_DEPLOYMENT_TARGET=14.0`）。主应用、Finder 扩展和三项内置引擎均为 x86_64，最低 macOS 14.0；完成后已恢复 ARM 开发引擎。
- 与 0.0.8 相比的构建差异：本机 Xcode 27 SDK 下 `MACOSX_DEPLOYMENT_TARGET` 环境变量不再影响 clang 生成 ArchiveBridge 的最低系统版本，需在编译命令显式追加 `-mmacosx-version-min=14.0`；封版脚本按二进制逐一断言后拦截过该差异。
- 两种应用包的主应用与扩展版本均为 0.0.9 / build 9；MIT、第三方声明、7-Zip 许可摘要及 LGPL 正文与仓库源文件一致。
- 内置引擎、Finder 扩展和主应用由内向外临时签名；Finder 扩展保留沙箱 entitlement，严格嵌套签名和安装产物隐私检查通过。未经 Developer ID 签名或 Apple 公证。
- 项目标准门禁、文档相对链接、暂存区隐私路径及差异格式检查通过。

## 真实更新验证（0.0.8 → 0.0.9）

应用内更新链路未实测：发布当日 Gitee Release 尚未创建，无从触发；本机 0.0.9 由开发期 `scripts/install-local.sh` 重装获得（/Applications 遗留的 `FastBudo.app.bak.*` 为该脚本旧行为的备份，非应用内更新产物，均已清理），不能作为更新链路证据。

发布侧验证已完成：

- Gitee v0.0.9 Release 含四个附件；匿名 `/releases/latest` 返回 `v0.0.9`。
- 从 Gitee 下载 `SHA256SUMS.txt` 与 arm64 安装包（4,823,161 字节），SHA-256 与本地封版产物一致。

应用内「检查 → 下载 → 安装 → 重启」的端到端真实更新待更高正式版发布时验证；0.0.9 → 0.0.10 轮次亦未执行，见[0.0.10 发布验证](2026-11-06-release-0.0.10.md)。

## 验证边界

Intel 仅交叉编译，未做真机验收。真实多显示器混合缩放、长期驻留、Developer ID 签名、公证及 Gitee 匿名更新限流下的端到端更新不在本轮验证范围；自动测试和本机探针不能替代这些验收。

“自动下载更新”开启后从启动检查到自动重启的完整链路复用手动更新已验证实现，本轮未实测发现更高正式版后的自动安装（无更高正式版可触发）；该边界将随下一个版本验证。
