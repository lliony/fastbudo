# 首版技术验证与验收记录

关联[设计](../superpowers/specs/2026-10-15-fastbudo-design.md)与[实施计划](../superpowers/plans/2026-10-15-fastbudo.md)。以下区分实际验证与尚未覆盖的范围，不将格式名称当作兼容性保证。

## 环境与构建

Apple Silicon、macOS 27.0.1、Xcode 27.0、Swift 6.4。SwiftUI/AppKit App 与测试共用 Xcode 工程；未创建没有实际复用需求的额外 Swift Package。project.yml 由本机已有 XcodeGen 生成，生成后的工程已纳入版本控制。

7-Zip 26.04 的完整格式库、CLI 和独立 C++ 桥接从固定官方源码构建，源包已随仓库保存。来源及 SHA-256 见 Vendor/7zip/manifest.json。该哈希是下载后的内容指纹，不是上游签名验证。

构建使用 `bash scripts/build-engine.sh` 后执行 xcodebuild。引擎通过 Xcode 标准资源复制阶段打包，没有关闭构建脚本沙箱。曾提出的关闭沙箱方案被自动审批拒绝，未执行，现方案不需要该变更。

## 路线调整依据

原型用两个 ZIP 分别保存 `a<换行>b` 与 `a_b`。7zz 文本列表逐字节相同，但实际解压的文件名不同。复现脚本：`python3 scripts/probe-7zip-listing.py /absolute/path/to/7zz`。

用户确认改用结构化桥接。现通过 IInArchive 读取原始条目，JSON 传递名称和大小；解压只获得应用提供的输出流。所有路径先验证，写盘使用目录句柄、openat、O_NOFOLLOW 与 O_EXCL。不再把 CLI 文本列表作为安全边界。

RAR 缺卷还可能返回“打开成功”，所以桥接同时检查归档错误属性及错误标志。该行为已由缺卷回归测试覆盖。

## 自动测试

桥接测试命令：`python3 -m unittest discover -s Tests/Bridge -v`，共 18 项测试。

| 范围 | 已通过的行为 |
|---|---|
| 路径与类型 | 原始换行/中文名称、绝对路径与穿越拒绝、大小写及 Unicode 碰撞、链接/硬链接/设备/FIFO 拒绝 |
| 输出保护 | 不跟随目标目录已有链接、不覆盖已有文件、空目录与内容恢复、修改时间恢复 |
| 展开量 | 高展开比在写盘前要求确认 |
| 加密与分卷 | 7z 加密头及连续分卷；ZIP AES/ZipCrypto 与标准 ZIP 分卷；RAR4/5 加密头、现代多卷、旧式 RAR4 多卷、缺卷失败 |
| 外部样本 | libarchive 3.8.1 固定测试集；文本内容和 CRC 与上游测试期望对应，不执行归档中的程序 |

Xcode 命令：`xcodebuild test -scheme FastBudo -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/xcode`。

覆盖服务文件 URL 转换、三种创建格式的内容往返、7z 与 ZIP 密码、错误密码、Mac 属性往返及干净模式、取消后源文件与暂存清理、只读输出目录、队列顺序及自动编号、普通隐藏文件/普通 ._ 文件保留、已识别 __MACOSX 元数据过滤。参数化测试的执行次数与测试定义数量不同，以 xcresult 汇总为准。

过滤测试发现 Foundation 会隐藏普通 ._ 条目，现使用真实目录项枚举，测试直接断言文件内容而非依赖同一目录枚举行为。

先行测试证据保留在本次工具执行记录中：服务转换、桥接原始路径/安全写入、分卷、输出提交、元数据过滤及修改时间曾观察到预期失败，修复后通过。属性往返与部分集成测试为能力验证，不宣称每个测试都执行过完整红绿循环。

## 空间不足验证

命令：`python3 scripts/test-low-space.py`。

创建独立 64 MiB HFS+ 测试磁盘映像，尝试解压容量超过可用空间的合成归档。任务失败，源归档 SHA-256 不变；测试卸载并删除自己创建的映像。没有填满用户主盘。

## 界面与系统入口

实际打开并读取了 FastBudo 的原生窗口。已观察到文件选择、格式、密码、元数据开关和任务结果呈现；布局增加最小高度，避免默认窗口隐藏表单首部。

两个系统服务已经在 Info.plist 声明并由 AppKit 注册；打开事件进入串行队列。Finder 菜单是否显示取决于安装位置和系统服务启用状态，自动测试不代替用户系统中实际菜单可见性检查。应用不会改变默认打开方式。

## 文件与密码边界

压缩先暂存内容；解压先复制当前归档系列到专用快照，再由桥接检查并写入独立输出目录。最终结果同卷独占重命名；重名自动编号。失败/取消只清理当前任务创建的目录；中断残留路径留在本地记录中，重启仅提示、不自动删除。

密码经 stdin 传递。已验证密码管道可工作且输出不回显密码；代码不将密码写入参数、环境变量、配置或临时文件。没有进行面向其他进程内存的安全审计。

## 未覆盖与交付边界

- 未验证 Intel、其他 macOS 版本、Windows/Linux 接收端或第三方所有解压器。
- 未做开发者签名、公证、App Store、自动更新、远程仓库发布或安装包上传。
- 未验证每个归档条目各自使用不同密码的特殊包、超百万条目包及所有错误编码变体。
- 权限和空间故障已用合成数据验证；没有模拟物理磁盘断电或文件系统损坏。
- 首版拒绝链接/特殊条目，不能当作完整系统备份工具。
