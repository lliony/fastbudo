# FastBudo 首版产品与技术设计

## 1. 目标与边界

开发免费、自用优先且准备开源的 macOS 压缩工具。工作名 FastBudo 来自当前项目目录，不作为已确定的发布品牌。主要从 Finder 操作，默认生成适合跨平台分享的干净压缩包。所有文件处理在本地完成，不需要账号或服务器。

已确认的体验：快捷 ZIP、更多压缩选项、打开压缩包解压、可配置元数据、密码包与常见分卷解压。首版不包含包内浏览或编辑、分卷压缩、冷门格式扩展、自动更新、遥测、云服务、Intel 验证及商店发布。

验证环境：Apple Silicon，macOS 27.0.1；本机已安装 Xcode，Swift 6.4。以上为本机命令输出，不代表已验证的最低系统版本。首版只承诺本机环境；扩展兼容范围需另行测试。

本文合并需求、设计与验收，不另设重复的需求文档。用户已于 2026-10-15 确认完整设计，状态为 active；设计确认不等于技术风险已经验证。

## 2. 用户流程

### 2.1 Finder 入口

采用 AppKit 系统服务，在应用 Info.plist 中声明两个 NSServices 项目，接收选中的文件 URL：

- “FastBudo：快捷压缩 ZIP”：使用已保存的元数据设置，默认干净分享，无密码。
- “FastBudo：更多压缩选项”：显示格式、文件名、位置、密码和元数据设置小面板。

入口以 Finder 的“服务”菜单为基线，不承诺右键顶层位置。安装到 Applications 并首次启动后提供启用说明，具体显示和多选行为必须在目标系统实测。服务回调仅接收任务，耗时操作异步进行。

Apple 明确说明 Finder Sync 不是通用 Finder 界面修改工具，因此首版不采用全盘监控的 Finder Sync 扩展。压缩包打开通过文档类型注册和 AppKit 打开事件接入；用户自行选择是否设为默认应用，应用不主动改变系统关联。

### 2.2 压缩

单文件或单目录以原名作为包名，多选默认“归档.zip”，同名输出自动加编号。单目录保留该目录作为包内顶层，多选以各项目名称作为顶层；不保存本机绝对路径。

默认输出到输入所在目录；跨目录选择默认使用第一个输入的父目录并在更多选项中可修改。不同来源出现同名顶层项时停止并说明冲突，不静默合并。自动命名与最终写入都要防止并发覆盖。

更多选项支持 ZIP、7z、tar.gz。ZIP 与 7z 支持密码；tar.gz 隐藏密码选项。输入去重；选中目录及其子项时仅保留父项。输出及临时文件不得被重新收入输入树。

压缩写到目标卷的专用临时位置，完整成功后以不覆盖方式提交为最终文件；失败、取消时不删除或修改源文件。压缩期间源文件变化导致无法保证一致性时明确报错，不宣称备份快照。

### 2.3 解压

默认在压缩包旁创建以包名命名的独立文件夹，不自动拆掉包内顶层目录。同名目标自动编号，不覆盖旧内容。无写入权限时提示选择其他输出目录。解压成功后在 Finder 中显示结果。

分卷从首卷打开，其他卷位于同目录；从后续卷打开时提示定位首卷。缺卷、损坏、错误密码分别给出可理解的错误，不当作成功。保留原包及所有分卷。

较长任务显示进度和取消；无法准确计算时显示当前阶段与已处理量，不伪造百分比。首版任务串行排队，减少并发磁盘开销；密码仅保留在当前任务内存中，完成或取消后释放。

## 3. 格式与加密范围

| 格式 | 创建 | 解压 | 密码与分卷目标 |
|---|---|---|---|
| ZIP | 是 | 是 | 创建 AES-256；解压 AES 和传统 ZipCrypto 样本；验证标准 .z01/.zip 分卷 |
| 7z | 是 | 是 | AES-256，带密码创建时启用文件名加密；验证 .7z.001 连续分卷 |
| tar.gz | 是 | 是 | 先 TAR 再 GZIP，无密码、无分卷承诺 |
| RAR | 否 | 是 | 验证 RAR4、RAR5、密码包及 .part1.rar / .rar+.r00 常见分卷 |

此表是验收目标，不是已通过的兼容列表。实施前先验证这些样本；若某项失败，修正引擎方案或明确向用户说明范围调整，不静默删掉需求。每个已发布支持项需记录引擎版本和可再分发测试样本来源。

密码 ZIP 使用强加密，面板提示部分系统自带解压器不兼容，且 ZIP 文件名不保密；需要文件名保密时推荐 7z。不默认提供弱加密创建。

## 4. 元数据策略

两个预设：“干净分享”（默认）、“保留 Mac 属性”。高级选项为“过滤 .DS_Store”和“保留 Mac 专有属性”，记住用户选择；快捷压缩始终是 ZIP，无密码，使用已保存的元数据策略。

干净分享递归排除 .DS_Store，不生成资源叉、扩展属性及其 AppleDouble 包装；保留普通隐藏文件，例如 .gitignore。保留文件内容、修改时间以及格式和引擎可可靠表达的基本权限，不承诺所有属性跨格式完全一致。

不能仅凭 ._ 前缀或 __MACOSX 目录名删除内容：只有识别为 AppleDouble 且可与对应文件关联的元数据才可排除；无法判定时保留，避免误删用户文件。过滤规则只影响输出，不清理源文件。

“保留 Mac 属性”首选评估 macOS 自带 ditto 的 ZIP 路径。启用前必须通过资源叉、扩展属性、Finder 标签的压缩及本应用解压往返测试。未验证的格式禁用该选项并说明原因；不为 7z、tar.gz 宣称完整 Mac 备份能力。ditto 路径与密码组合也必须验证，不支持的组合不得默默降级。

解压正常的 Mac 元数据包时必须正确恢复对应属性，或明确报告不支持；不能把仅生成 ._ 文件描述为属性已恢复。

## 5. 技术方案

采用 Swift + SwiftUI 构建设置、小面板与任务窗口，AppKit 接入系统服务和文件打开事件；简单设置用 UserDefaults。首版直接分发本地 .app，不引入数据库、Web 壳或服务端。签名、公证及正式二进制发布在发布阶段处理，不属于本次设计落地。

首选随应用提供官方 macOS 7-Zip 命令行引擎（7zz）；实现时固定具体版本、下载来源及校验值。官方 26.04 下载页提供 macOS arm64 / x86-64 包，格式页覆盖 ZIP、7z、TAR、GZIP 创建和 RAR 解压，不能据此推断所有分卷变体均可用。

仅三个职责边界，先用普通 Swift 类型实现，不搭插件框架：

1. 系统入口与界面：将 URL 和用户选项组成任务，呈现进度、密码与错误。
2. 任务处理：校验输入、命名输出、过滤元数据、排队、取消、临时文件和结果提交。
3. 引擎调用：固定可执行文件路径、传入参数、消费输出与退出码；必要时单独处理保留属性的 ZIP 路径。

数据流：Finder/打开事件 → 任务参数 → 输入与输出校验 → 元数据/格式路由 → 引擎 → 安全检查与提交 → Finder 展示。

执行外部进程使用参数数组，不拼 shell 字符串。以用户可控文件名开头的连字符、换行、Unicode 和选项注入都要覆盖。密码不得出现在进程参数、环境变量、日志或临时文件中；先验证引擎交互式密码通道可否安全自动化，失败则调整集成方式，不用明文命令行参数绕过。

### 5.1 方案取舍

| 方案 | 性能开销 | 生态与人才 | 长期维护 | 许可风险 | 迁移成本 |
|---|---|---|---|---|---|
| Swift 原生 + 7zz（选择） | UI 开销小，压缩由引擎承担 | Apple 生态成熟，需要 Swift/AppKit 经验 | 无跨平台 UI 层，需维护引擎升级 | LGPL/BSD/unRAR 条款需落实 | 更换引擎可局部完成；跨平台 UI 需重写 |
| 系统脚本封装 | 小 | Shell 易入门，完整桌面交互能力弱 | 多格式与安全交互会推高脚本复杂度 | 仍须审计外部引擎 | 数据无迁移，UI 与任务控制需重做 |
| Electron/Tauri | 引入额外运行时或工具链 | Web 人才较多，系统集成仍需原生能力 | 当前无跨平台收益，依赖更多 | 壳和引擎均需审计 | Web UI 可复用，Finder 入口仍需迁移 |

不自研压缩算法，也不依赖用户安装 Homebrew。替换引擎属于可逆决策；绑定原生 UI 是有意接受的 Mac 优先取舍。

## 6. 文件安全与异常处理

- 解压前校验条目路径，拒绝绝对路径、目录穿越及目标系统下冲突的路径；覆盖大小写/Unicode 归一化碰撞与重复条目。
- 临时目录本身不是安全隔离。链接条目不得被引擎跟随到输出树外；首版不接受归档内的符号链接、硬链接和设备条目，必须在写盘前识别并拒绝。安全行为未经验证不得发布通用解压。
- 压缩输入中的符号链接不得跟随读取树外文件；首版遇到链接明确报错，不能静默省略。此限制需在使用说明中列出。
- 解压到输出卷的专用临时目录，完整校验成功后不覆盖地移动到最终目录。不能先在任意路径写完再检查是否越界。
- 解压前预计超过 10 GiB、100,000 条目或 1000 倍展开比时要求确认；无法预估时先说明并确认。运行期间继续核算实际写入量和空间；预估偏小越过阈值时暂停或终止后确认重试，空间不足立即停止。
- 用户确认大包不豁免路径和链接规则。保留安全余量，处理引擎异常退出、磁盘满、无权限、损坏数据和取消。
- 失败清理仅限本任务创建的路径；清理失败则报告残留路径，不递归清理用户目录。重启后只识别并提示本应用拥有的未完成临时任务。
- 不启用递归解压，不主动执行解压所得文件，不主动移除下载隔离属性。只清理输出包内指定的分享元数据。

## 7. 开源与分发

建议自有代码采用 MIT；在用户审阅设计后实施时写入许可证文件，不把该建议当作已经授权所有第三方代码使用 MIT。第三方引擎保留独立许可证和版权声明。

7-Zip 官方许可包含 LGPL 2.1 或更新版本，以及部分 BSD 和 unRAR 限制。分发二进制时必须附带相关许可，按实际包与链接方式落实 LGPL 的对应源码供应等义务，记录源码、构建步骤和修改。unRAR 代码不得用于重建 RAR 压缩算法。单独子进程调用不免除引擎自身的分发义务。

首版不开公开仓库、不上传安装包、不购买开发者账号；公开发布和项目命名由用户另行决定。免费自用不依赖收费服务；面向他人的签名、公证分发可能涉及开发者计划费用。

## 8. 验收与进入实施的条件

先进行四项针对性技术验证，再展开完整实现：Finder 服务接收多选文件；官方引擎格式/密码/分卷样本；安全密码通道；元数据与安全解压。任一结果与本文冲突时更新设计并说明影响。

| 验收项 | 通过标准 |
|---|---|
| 内容正确 | 各创建格式往返后文件哈希一致，空目录和中文文件名保留 |
| 干净分享 | 不额外生成 Mac 元数据；普通隐藏文件及非元数据的 ._ 文件保留 |
| 属性模式 | 在开放的组合中资源叉、扩展属性、标签可被本应用正确还原 |
| 密码 | 正确密码成功、错误密码重试；参数、日志和临时文件中无密码 |
| 分卷 | 表中样本逐项成功，缺卷和后续卷入口反馈明确 |
| 安全 | 穿越、链接、重复/归一化碰撞、超限样本不会产生越界写入 |
| 数据保护 | 重名、无权限、空间不足、取消和引擎崩溃不破坏源文件及已有目标 |
| 桌面集成 | 本机 Finder 服务、打开方式、长任务进度与取消均可用 |
| 开源可构建 | 构建说明含版本与来源，第三方声明完整，用户无需额外安装压缩工具 |

测试使用合成数据和许可允许的样本。文件安全、过滤、命名和任务取消有自动测试；Finder 菜单及权限提示做本机手工验证。跨平台兼容在没有第二系统验证时明确标为未验证，不靠格式名称推断。
