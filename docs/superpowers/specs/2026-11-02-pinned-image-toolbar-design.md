# 贴图拖动与响应式工具栏

本设计细化既有[截图与贴图第一批设计](2026-10-26-screenshot-pin-design.md)中的贴图交互。入口见[文档索引](../../README.md)，实施步骤见[计划](../plans/2026-11-02-pinned-image-toolbar.md)。

## 目标与范围

- 鼠标在贴图图片区域按下并拖动时，直接移动当前贴图窗口；不再要求先命中标题栏，也不新增移动按钮。
- 缩小、放大、逆时针旋转、顺时针旋转、水平翻转、垂直翻转、透明度和复制各有独立的小图标按钮；穿透、隐藏和关闭不进入工具栏或“更多”。
- 工具栏宽度足够时显示全部功能，不显示“更多”；宽度不足时只将放不下的功能收入“更多”，已显示按钮仍直接执行。
- 保留既有图片变换、15% 透明度下限、菜单栏恢复隐藏或穿透贴图、数量与像素预算，不新增贴图持久化、分组或历史能力。

## 交互设计

图片区域覆盖一个只负责原生窗口拖动的 AppKit 命中层。命中层在主键按下时记录鼠标屏幕坐标与窗口原点，拖动时按屏幕坐标增量移动所属面板；工具按钮、透明度弹层和“更多”菜单不触发窗口移动。标题栏原有移动能力保留，鼠标穿透开启后窗口不再接收拖动或按钮事件，仍通过菜单栏恢复。

工具动作使用统一的 `PinnedImageAction` 列表。标准显示顺序为：缩小、放大、逆时针旋转、顺时针旋转、水平翻转、垂直翻转、透明度、复制。每个按钮为 28×28 点，间距 4 点，工具栏水平内边距各 8 点；由纯布局策略根据实际可用宽度切分直显动作与溢出动作。

空间不足时先保证缩小、放大、复制和透明度等高频动作直显，再依次保留旋转和翻转；直显按钮仍按标准顺序排列。“更多”仅在溢出列表非空时出现在末尾，并只列出当前未直显的动作。透明度按钮打开沿用 15%～100% 的滑杆弹层；从“更多”选择透明度时打开同一弹层，不提供不同的第二套控制。

水平和垂直翻转在状态生效时保持高亮；透明度低于 100% 或弹层打开时高亮。缩放、旋转和复制属于即时动作，点击后不保留伪选中状态。所有按钮与菜单项使用一致的中文帮助和辅助功能标签。

## 组件与数据流

`PinnedImage` 继续持有图片、变换状态和 `PinnedImagePanel`，并集中执行 `PinnedImageAction`。透明度动作返回“打开弹层”效果，其余动作直接复用现有模型行为，因此直显按钮和“更多”菜单不维护两套执行逻辑。`PinnedImageToolbarLayout` 只接收可用宽度并返回 `visible` 与 `overflow` 两组动作，不读窗口或图片状态，便于边界测试。`PinnedImageView` 负责按结果渲染图标按钮、“更多”菜单及透明度弹层；图片拖动层只改变所属窗口原点，不修改图片数据或工具状态。

窗口缩放或图片旋转导致内容宽度变化时重新计算布局。可用宽度达到 268 点、足以容纳全部 8 个按钮时不预留“更多”宽度；存在溢出时先预留一个 28 点“更多”按钮，再计算直显数量。异常的零或负宽度返回空直显列表和完整溢出列表，不产生越界或负容量。

## 验收与验证边界

自动测试覆盖：全部按钮恰好可见的阈值、阈值下方出现“更多”、最小窗口宽度、零或负宽度、直显优先级、溢出顺序、无重复/遗漏动作、翻转和透明度高亮状态，以及图片拖动事件产生正确窗口坐标增量。既有变换、恢复和资源边界测试继续通过。

真实应用验收覆盖：在图片内部拖动贴图；按钮、弹层和菜单操作不误拖；宽窗无“更多”，逐步缩窄时仅溢出放不下的动作；从直显按钮与“更多”执行同一动作结果一致；穿透后可从菜单栏恢复。自动测试不能替代多屏边缘、不同缩放比例和鼠标穿透后的真实系统交互验证。
