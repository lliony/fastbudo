# 截图标注工具修复设计

见[实施计划](../plans/2026-11-02-screenshot-annotation-editing.md)和[索引](../../README.md)。

## 问题与现状

0.0.6 本机安装版来自截图整合分支。当前截图编辑器同时存在四条独立路径：独立浮窗、区域截图原位编辑、标注画布和 SwiftUI 工具面板。它们共用 `ImageEditor`，但几何和状态边界没有收拢，导致以下问题：

1. **工具落在截图外**。独立浮窗的 `editorFrame` 分别对宽高取下限 `240×120`，极小或极宽图片的窗口宽高比被破坏，画布按比例居中后出现留白；右下角工具按窗口而不是按图片定位，落在留白里。区域截图原位编辑更直接：`inlineEditorFrame` 为保证工具可点，把 240×120 的工具区并入选区，`controlsFrame` 取并集后的区域，小选区的按钮必然在截图外。`docs/guides/screenshot-pin.md:15` 甚至把“小选区允许工具显示在选区外”写成既有行为。
2. **箭头、画笔不可用**。工具按钮在 popover 中点击后只执行 `model.tool = tool`，popover 不关闭，`annotating` 仍由另一个画笔按钮控制；用户选完工具回到画布，第一次按下往往被 popover 当作“点击外部”吞掉，画布仍处于拖图状态。标注入口和工具选择是两个互不联动的开关。
3. **文字是“先输入再贴入”**。文字内容存在 `model.text`，必须在 popover 的 TextField 输入，再点击图片把整段文字画上去；画布上没有光标，无法边看位置边输入。
4. **切工具卡帧**。`updateNSView` 无条件 `view.needsDisplay = true`，切换工具、开关 popover、停留提示等任何 SwiftUI 状态变化都会触发整幅画布重绘；重绘时逐条重放全部标注，每条马赛克都要重新裁剪、缩放、插值。重绘成本随标注数量线性增长。

安装版本（Oct 28 20:20）早于分支 `cbf16a0`（Oct 28 21:28）的原位编辑提交，因此用户看到的是独立浮窗编辑；主分支与整合分支的两条路径都必须修。

## 目标与非目标

**目标**

- 工具条固定在图片下方外侧并右对齐，不压住截图；下方放不下时翻到上方，仍放不下才重叠进图片。
- 选中任一标注工具即进入标注，下一次在画布按下就绘制；箭头、画笔、矩形、椭圆、马赛克行为一致。
- 文字工具改为在图片上点击后出现插入光标，就地输入，回车或点击别处提交。
- 切换工具、开关工具面板、停留提示不重绘画布；已完成标注缓存为位图，绘制中的标注只重绘自身。
- 保持一次 Escape 关闭当前截图、导出不包含工具层、不覆盖已有输出等既有约束。

**非目标**

- 不引入富文本、文字选择、多行排版、字体选择或标注编辑/删除。
- 不改变截图捕获、合成器等待、临时目录、20 MiB/四千万像素上限。
- 不新增第三方依赖，不改变 Xcode 工程结构（`project.yml` 不变）。
- 不改变工具条的按钮组成与快捷键。

## 交互设计

### 工具条位置

- 编辑器先计算图片显示矩形（aspect-fit，居中）；工具条放在该矩形**下方外侧**，右边缘与图片右边缘对齐，间隔 8 点，不覆盖任何图片像素。
- 下方到屏幕边缘放不下时翻到图片**上方外侧**；上下都放不下（例如全屏截图）才重叠进图片右下角，并把位置钳制在屏幕内。
- 工具条跟随图片缩放和原位拖动；拖图时画布、选区、工具条一起移动，窗口本身不动。
- 工具条宽度不足时仍按图片宽度收敛：常规一排 8 个按钮；图片显示区域小于常规工具条时改为两排 4 个。

### 工具选择

- 画笔按钮只负责进入/退出标注：进入后下一次按下即绘制，再点一次恢复拖图。
- 画笔按钮右侧新增当前工具按钮，图标随当前工具变化；点击展开工具面板。
- 工具面板中点任一工具后立即写入 `model.tool`、置 `model.isAnnotating = true` 并关闭面板，用户回到画布直接拖动即可绘制。
- 颜色、笔宽调整不关闭面板，可连续调整；面板关闭只影响可见性。
- 撤销、重做仍只由按钮和 ⌘Z/⇧⌘Z 触发，不改变当前工具和标注状态。

### 文字

- 文字工具下在画布点击：以点击位置为文字左上角插入一个无边框 `NSTextField`，窗口焦点移入，出现插入光标。
- 输入内容直接覆盖在图片上，字体、字号、颜色与最终导出一致；字号仍为 `max(16, 笔宽 × 5)` 个图像像素，按当前显示比例换算为界面点。
- 回车提交；点击画布其他位置、点击工具条、退出标注、导出或关闭都会先提交当前文字。
- 空文字（含纯空白）不生成标注；超过 2000 字符截断。
- 文字提交后成为普通 `ImageAnnotation`，可撤销；提交不退出标注，可继续点下一个位置。
- Escape 仍直接关闭整个截图编辑器（含未提交文字），与 2026-10-27 设计一致。

### 拖图

- 未进入标注时，独立浮窗拖动图片移动窗口；原位编辑拖动图片只移动选区、画布与工具条。
- 进入标注后，按下必须产生标注，不再触发窗口拖动或选区移动。

## 布局与降级

### 图片显示矩形

新增纯几何 `EditorLayout`，SwiftUI 定位与 AppKit 画布共用同一份计算，避免“按钮按图片算、点击按画布算”：

- `imageRect(in:imageSize:)`：在给定矩形内等比缩放并居中，不做 1:1 限制；极小图片会放大到可用区域，放大只影响界面显示，导出仍用原始像素。
- 画布的 `imageRect` 直接调用它，坐标换算、裁剪、绘制统一。

### 工具条尺寸

- 常规：8 个 28×28 按钮、间距 4、内边距 6，内容约 `296×72`；含 8 点四周留白后外框 `312×88`。
- 紧凑：两排各 4 个，内容约 `152×92`，外框 `168×108`。
- `usesCompactControls(in:)` 按图片显示矩形是否放得下常规工具条决定；`toolbarOrigin(imageRect:toolbarSize:in:)` 负责“下方外侧 → 上方外侧 → 图片内”的回退。

### 原位编辑门槛

区域截图只要选区面板存在就原位编辑，不再按选区尺寸回退独立浮窗：

- 选区矩形不变，图片按选区等比填满；工具条落在选区下方外侧的灰显区，若选区贴屏幕底边则翻到上方。
- 独立浮窗用 `editorFrame` 计算图片区域后，窗口再为工具条预留高度：图片顶部居中，工具条在图片下方外侧。
- 极端比例（如 `300×5000`、`6000×300`）由屏幕可用区域钳制窗口与工具条；上下都放不下时工具条重叠进图片，但不落到窗口/屏幕角。
- 由此移除 `inlineEditorFrame`、`controlsFrame`、`fitsToolbar` 和“小选区回退独立窗口”的旧取舍。

## 渲染与性能

- `model.revision` 只在标注集合变化（append/undo/redo）时递增。当前工具、标注开关、颜色、笔宽、提示文案都不递增。
- `AnnotationCanvas.sync(model:revision:annotating:onClose:onMove:)` 仅在 revision 变化时置 `needsDisplay = true`；工具切换只更新状态，不触发画布重绘。
- 画布缓存“已完成标注 + 原图”的合成位图：`backdrop` 按 revision 惰性生成，一次 `draw` 内最多生成一次；绘制中的 `pending` 单独叠加，不重放全部标注。
- 文字输入框是画布子视图，输入过程不经过画布重绘；提交走 `append`，只重绘一次。
- 生成的位图位于主线程，但只随 revision 变化，不再随每次状态更新重建；撤销/重做一次性重建。
- 标注上限仍为 200 条，避免无界缓存和导出耗时。

## 代码影响

- `App/Screenshot/ImageEditor.swift`
  - 新增 `EditorLayout`（纯几何）。
  - `ImageEditorModel`：新增 `isAnnotating`、`select(_:)`；`draw(_:)` 改为可供画布复用的 `draw(annotation:)`；移除 `text`。
  - `ImageEditor`：删除 `controlsFrame`；body 改为按 `imageRect` 定位工具层；新增当前工具按钮；文字面板去掉 TextField。
  - `AnnotationCanvas`：`imageRect` 改用 `EditorLayout`；新增 `sync`、`backdrop` 缓存、文字输入框与提交逻辑。
- `App/Screenshot/ScreenshotController.swift`
  - `editorFrame` 等比放大。
  - `edit(_:in:selectionFrame:)` 不再计算/传入 `controlsFrame`。
  - `editCapturedImage` 只要选区面板存在就原位编辑，不再按尺寸回退。
  - 删除 `inlineEditorFrame`。
- 测试：`AppTests/ImageEditorTests.swift`、`AppTests/ScreenshotTests.swift`。
- 文档：截图指南、架构文档截图段、变更日志未发布区、文档索引。

## 验收

**自动测试**

- `EditorLayout`：宽图、方图、零尺寸、紧凑阈值、原位门槛。
- `editorFrame`：800×600@2 仍为 400×300；400×100@2 等比放大为 480×120；80×40 为 240×120；极端比例仍在屏内且不小于 240×120。
- 六工具中矩形、椭圆、箭头、画笔、马赛克通过合成 `NSEvent` 在画布产生标注；文字通过输入框提交。
- 工具切换不置 `needsDisplay`；同一 revision 连续绘制只生成一次 backdrop；append 后重建一次。
- 文字：点击出光标、提交生成标注、空文字不生成、回车提交。
- 既有 Escape、复制、保存、撤销/重做、Retina 像素、无覆盖保存测试保持通过。

**真实系统检查**

- 普通区域、极小区域（如 40×30 点）、贴屏幕底边的选区、全屏截图各截一次，确认工具条落在图片下方外侧；底边无空间时翻到上方，全屏时才重叠。
- 箭头、画笔各画一笔；选工具后第一次按下即绘制。
- 文字工具点击后直接输入并回车，位置与导出结果一致。
- 打开大截图（约 4000×3000），连续切换六个工具和颜色/笔宽，确认无卡顿。
- 多屏混合缩放、Intel 机器本次不声称已验证；自动测试与隔离窗口不等同于实机截图流程验收。

## 兼容与取舍

- 2026-10-27 设计的 Escape 语义不变：工具面板打开或文字输入中，一次 Escape 仍关闭当前截图；保存面板先取消。
- 2026-10-28 原位编辑设计中“极小选区保留工具操作区、工具可在图片外”被本设计取代；工具条固定贴图片外侧，不再并入选区，也不再把“图片外”当作缺口。
- 编辑阶段仍不写入剪贴板、不覆盖已有输出；复制/保存/贴图继续共用同一渲染结果。
- 小选区回退需要短暂关闭选区遮罩再显示独立窗口，可能出现一次窗口切换；相比工具不可点，这是可接受代价，并在指南中写明。
