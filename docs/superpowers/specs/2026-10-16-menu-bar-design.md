# 菜单栏图标收纳设计

## 目标与已确认范围

在 FastBudo 中增加其他应用的菜单栏图标收纳。用户已确认使用原菜单栏展开、收起，并通过按住 ⌘ 拖动调整位置和顺序。聊天中的设计已确认；本文等待书面审阅，尚未实施或完成兼容性验证。

首版仅提供常驻区与收纳区，设置入口为「菜单栏」。不增加独立图标浮窗、第三方应用列表、自动排序、永久隐藏、定时收起或逐应用规则；不承诺移动系统固定项目。

## 用户交互

首次安装默认关闭此功能，避免改变现有菜单栏。启用后显示独立收纳按钮与分隔标记；FastBudo 现有工具入口继续提供剪贴板、任务、设置和退出。

展开状态下，用户按住 ⌘ 拖动可移动图标：分隔标记左侧为收纳区，右侧为常驻区。按当前位置自然排序，不由 FastBudo 重排。收纳按钮应留在常驻侧，提供明确的展开/收起说明及辅助功能标签。

点击收纳按钮在展开与收起间切换。展开后用户直接点击原应用图标，使用原应用的菜单和弹窗。首版不代替第三方应用接收点击。

设置提供「启用菜单栏收纳」和「启动时收起」两个开关，后者默认关闭，功能关闭时不可操作。只有启用收纳后才应用启动偏好；切换启动偏好不改变当前展开状态。设置同时说明 ⌘ 拖动与左右区域的关系，并提供「展开收纳区」操作，作为按钮位置异常时的恢复入口。

关闭功能或正常退出 FastBudo 时先恢复展开，再移除收纳控件。关闭设置窗口不关闭收纳功能，也不退出程序。强制结束后的系统恢复行为必须实测，不承诺应用能执行崩溃后的清理。

## 技术方案与取舍

沿用 Swift、SwiftUI、AppKit 和 UserDefaults，不新增第三方依赖。候选方案是由 AppKit 状态栏项承载收纳按钮与分隔占位项，通过改变占位宽度使左侧项目退出或恢复可见区域。这是待验证的布局策略，并非系统对第三方图标隐藏能力的保证。

相比枚举图标并模拟拖动，该方案不需要建立应用清单或自动控制其他应用；相比独立浮窗，它保留原应用交互。代价是受菜单栏布局、屏幕宽度、刘海及系统版本影响，窄屏展开也不能保证容纳全部图标。

预期仅增加一个由 AppDelegate 持有的菜单栏控制对象，管理状态栏项的创建、切换与释放。PreferencesView 绑定其设置与展开操作；AppDelegate 在启动、正常退出时调用生命周期方法。压缩和剪贴板模块不参与此功能。

数据流：设置或收纳按钮 → 控制对象 → 状态栏布局。UserDefaults 仅保存启用及启动收起偏好；图标顺序交由系统管理，应用不保存或恢复第三方坐标。不修改其他应用的偏好，不上传数据，不读取剪贴板内容。

首版目标是不引入辅助功能或屏幕录制权限、不调用私有 API。实施时先核对当前官方 API 与本机 SDK，再验证原型；若收纳目标必须依赖额外权限或私有 API，应报告结果并重新讨论方案，不能悄悄扩大权限。

## 状态与异常处理

状态只有关闭、展开和收起。关闭时无收纳控件；展开与收起只改变布局，不启动或退出其他应用。重复启用不能重复创建状态栏项。禁用后再次启用从展开开始，启动收起偏好只在应用启动时应用。

关闭功能与正常退出均撤销占位效果并释放自身控件；保持已有任务退出保护，不因收纳改变压缩任务的取消规则。正在执行任务而退出被取消时，不移除正在使用的收纳控件。

对不支持的布局不宣称收纳成功。验证失败则不默认启用该功能；记录失败场景，再调整方案。显示器切换与睡眠唤醒后必须能从设置恢复展开。图标位置的跨应用重启保留属于验证项，不能仅凭系统通常行为认定通过。

## 验证与交付标准

实施计划的第一项是独立、可撤销的收纳原型验证；它不接管或自动拖动用户的真实图标。先用自建测试状态栏项验证两区布局和恢复，再由用户手动拖入选定的第三方图标进行兼容性验证。只有原型通过后才接入正式设置与生命周期。

| 场景 | 验收标准 |
|---|---|
| 初次使用 | 默认关闭，不改变已有菜单栏 |
| 分区排序 | ⌘ 拖动可移动项改变顺序与所属区域；固定项不强行移动 |
| 收起与展开 | 收纳区可隐藏和恢复，常驻区与恢复入口可用 |
| 原应用操作 | 展开后图标点击仍打开原应用菜单或弹窗 |
| 关闭与退出 | 取消占位效果，无残留空白；退出被任务保护阻止时功能仍可用 |
| 重复切换 | 无重复按钮、重复观察者或失效状态 |
| 启动偏好 | 仅在启用功能时按偏好启动；设置正确持久化 |
| 后台常驻 | 关闭设置窗口后仍可收纳；不改变现有 Dock 隐藏行为 |
| 重启与唤醒 | 应用重启、目标应用重启、睡眠唤醒后可恢复展开；记录位置保持情况 |
| 屏幕布局 | 本机刘海屏、不同可用宽度、全屏及多显示器切换分别记录结果 |

自动测试覆盖状态转换、偏好恢复、重复启用与关闭清理；布局、⌘ 拖动和第三方菜单必须实机验证。只声明已经实测的平台；没有外接显示器等条件时明确标记未验证，不将其当作已兼容。不得为本功能采集屏幕或改动用户图标顺序作为无人值守测试。
