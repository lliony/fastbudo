# FastBudo 首版实施计划

> 面向执行者：使用 `executing-plans` 按任务执行；用户选择委派时改用 `subagent-driven-development`。先读关联设计，每个勾选步骤完成后更新状态。

**目标：** 交付可在用户 Mac 本地使用的 Finder 压缩工具，默认干净 ZIP，支持约定格式、密码与分卷解压。

**架构：** SwiftUI 提供选项和任务窗口，AppKit 接入系统服务与文件打开事件。普通 Swift 类型处理任务、文件安全和引擎调用；优先随包提供官方 7zz，ZIP 属性保留单独评估 ditto。不引入服务端或插件框架。

**技术栈：** Swift 6.4、SwiftUI、AppKit、Foundation、Swift Testing、官方 macOS 7-Zip。

**规格：** [已确认设计](../specs/2026-10-15-fastbudo-design.md)。本计划是执行顺序，不替代设计中的产品行为。

## 全局约束

- 验证环境：Apple Silicon，macOS 27.0.1；首版只承诺本机环境。
- 首版任务串行排队；快捷压缩始终是 ZIP，无密码，使用已保存的元数据策略。
- 创建 ZIP、7z、tar.gz；解压 ZIP、7z、tar.gz、RAR。密码、分卷目标逐项按规格 §3 验收。
- 密码不得出现在进程参数、环境变量、日志或临时文件中。
- 首版不接受归档内的符号链接、硬链接和设备条目，必须在写盘前识别并拒绝。
- 解压前预计超过 10 GiB、100,000 条目或 1000 倍展开比时要求确认；无法预估时先说明并确认。
- 临时目录不等于安全隔离；不得先执行不受约束的解压，再检查有没有越界。
- 不覆盖原文件，不移除下载隔离属性，不执行所得文件，不改变系统默认打开关联。
- 无账号、服务器、遥测、自动更新、分卷压缩、包内编辑或浏览、商店发布。
- 新增依赖只允许经验证确实需要的压缩实现；无 Homebrew 运行时依赖。
- 所有测试使用合成数据或可再分发的样本；不对用户真实文件测试失败、取消或空间耗尽。
- 中文提交并追加 `Co-Authored-By: Codex <codex@openai.com>`；只提交对应任务文件。

## 执行顺序与风险门槛

先完成任务 1–3，分别验证 Finder、引擎与安全路径。遇到失败保留证据，仅阻塞依赖该结果的任务，不擅自缩减用户已确认范围。密码、RAR/分卷或安全枚举不能成立时，先回到选型，不能用明文参数或简单文本解析凑齐功能。

任务 1–3 通过后依次完成 4–8。每项先写小测试、观察预期失败、实现、跑相关测试并提交。本文不提前生成应用代码，不把编译成功当作 Finder 或归档兼容性通过。

## 任务 2：官方引擎、密码通道与格式证据

**文件：** 创建 Vendor/7zip/、EngineProcess.swift、Tests/FastBudoCoreTests/EngineProcessTests.swift、Tests/Fixtures/manifest.json；更新验证记录和第三方说明。

**接口：** `EngineProcess.run(executable: URL, arguments: [String], workingDirectory: URL, password: String?) async throws -> ProcessResult`；`ProcessResult` 仅含 `exitCode: Int32`、`stdout: Data`、`stderr: Data`，生产日志不得直接输出原始流。任务取消必须终止并回收子进程。

- [ ] 读取官方包内帮助、许可证和密码读取实现。固定官方版本、URL、SHA-256 与源包；不从不明镜像下载。不将 7zz 当系统全局程序安装。
- [ ] 写非密码运行测试：对 `/usr/bin/true` 断言退出码 0，对 `/usr/bin/false` 断言退出码非零；取消休眠进程后断言子进程结束。

```swift
let result = try await EngineProcess.run(
    executable: URL(fileURLWithPath: "/usr/bin/false"),
    arguments: [], workingDirectory: temporaryDirectory, password: nil)
#expect(result.exitCode != 0)
```

- [ ] 运行 `swift test --filter EngineProcessTests`，确认尚无实现时失败；用 Foundation Process、并行消费 stdout/stderr 实现无密码路径，避免管道填满死锁。
- [ ] 验证密码提示是否能经匿名管道安全提供；如必须终端则验证受控 PTY、关闭回显、固定语言提示和取消。不能识别提示时超时终止，不盲发密码；不把密码拼进 `-p密码`。
- [ ] 测试随机密码创建和解压 ZIP AES、7z 加密头，错误密码重试；用 ps 检查参数，用受控捕获检查输出和临时文件不含密码。记录所用标志及引擎行为，成功前不开放加密功能。
- [ ] 对规格 §3 全部格式逐项记录样本结果，包含 ZIP AES/ZipCrypto、标准 ZIP 分卷、7z 分卷、RAR4/5 及两类 RAR 分卷；样本缺失记为阻塞，不伪造通过。RAR 样本优先取许可明确的上游测试集，不新增 RAR 创建功能。
- [ ] 重跑 EngineProcessTests；提交“功能：接入压缩引擎与安全密码通道”。若密码通道失败，仅提交验证证据并重新评估引擎集成，后续依赖加密部分保持阻塞。

## 任务 3：条目枚举与安全解压门槛

**文件：** 创建 ArchiveSafety.swift、Tests/FastBudoCoreTests/ArchiveSafetyTests.swift、危险归档测试样本；更新验证记录。

**接口：** `ArchiveEntry(path: String, kind: EntryKind, size: UInt64?)`，kind 为 file/directory/symlink/hardlink/special；`ArchiveSafety.validate(entries: [ArchiveEntry], compressedBytes: UInt64, caseSensitive: Bool) throws -> ExpansionDecision`，结果为 allowed 或 needsConfirmation；无法可靠枚举时抛错，不猜测为普通文件。

- [ ] 从已固定引擎中验证是否有无歧义的条目枚举方式，重点验证换行、等号和伪造字段的文件名。不能把 `7zz l -slt` 的简单按行切割作为安全边界；加密目录必须先取密码后枚举。
- [ ] 若 CLI 无法可靠识别路径及链接类型，停止通用解压实施，评估引擎 API 的结构化枚举/流式输出，并把新增桥接文件和许可影响补入本计划；未经这个门槛不得运行任意归档的磁盘解压。
- [ ] 添加路径穿越、绝对路径、链接、硬链接、特殊条目、重复条目、大小写碰撞和 Unicode 等价路径测试。

```swift
#expect(throws: (any Error).self) {
    try ArchiveSafety.validate(
        entries: [ArchiveEntry(path: "../outside", kind: .file, size: 1)],
        compressedBytes: 1, caseSensitive: false)
}
```

- [ ] 运行 `swift test --filter ArchiveSafetyTests` 观察预期失败；逐路径分量规范化，拒绝根路径和 ..，按目标卷敏感性检查碰撞，以溢出安全方式累加字节数；未知体积和超过规定阈值返回 needsConfirmation。
- [ ] 测试 TAR 两阶段解压：外层 GZIP 只输出受控临时 TAR 文件，再枚举内层，安全检查完成才写入最终暂存树。
- [ ] 以外部哨兵文件验证恶意样本无法写出目标树；预检与写入间使用同一不可变归档副本或等价的稳定句柄，避免归档被替换。运行时容量监控和终止必须在发布前验证。
- [ ] 重跑安全测试；提交“功能：建立归档安全校验边界”，验证记录列出可支持的安全解压路径。
