# 菜单栏图标收纳 Implementation Plan

> 已按用户要求移除菜单栏收纳功能。本文仅保留历史记录，不再适用于当前版本；FastBudo 原有菜单栏工具入口仍保留。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 沿用用户之前的顺序执行选择，不委派。

**Goal:** 在 FastBudo 中以原菜单栏展开和收起其他应用图标，支持用户 ⌘ 拖动分区排序。

**Architecture:** 先用独立 AppKit 原型验证宽占位项收纳方案。通过后以一个主线程控制对象管理状态栏项和偏好，由 AppDelegate 管理生命周期，SwiftUI 提供设置；第三方图标顺序交由系统维护。

**Tech Stack:** Swift 6、AppKit、SwiftUI Observation、UserDefaults、Swift Testing；不新增依赖。

**Spec:** [菜单栏收纳设计](../specs/2026-10-16-menu-bar-design.md)。返回[文档索引](../../README.md)。

## Global Constraints

- 当前兼容基线为 Apple Silicon / macOS 27；其他版本必须实测后再声明。
- 首次安装默认关闭此功能，避免改变现有菜单栏。
- 首版仅提供常驻区与收纳区，设置入口为「菜单栏」。

## 任务一：验证收纳机制与恢复路径

**接口：**独立临时 AppKit 进程，不导入 FastBudo，不保存用户偏好；产出实际支持的项布局、展开/收起长度及恢复证据。后续任务依赖本任务通过，不能仅凭 API 存在判定收纳成功。

- [x] 核对本机 SDK 的 NSStatusBar、NSStatusItem 接口及官方资料。版本事实优先 Context7；不可用时直接读取 Apple 官方原文，记录来源与日期。不使用私有排序键或 KVC。
- [ ] 创建临时原型，从以下核心开始，以独立 NSApplication delegate 强持有全部状态栏项：

```swift
let bar = NSStatusBar.system
let toggle = bar.statusItem(withLength: NSStatusItem.squareLength)
let divider = bar.statusItem(withLength: 16)
let sample = bar.statusItem(withLength: NSStatusItem.squareLength)
toggle.button?.title = "‹"
divider.button?.title = "│"
sample.button?.title = "测"
// 候选宽度仅用于实测，不是已确认的平台常量。
divider.length = 10000
// 展开与退出均恢复长度；退出还须移除自身全部项目。
divider.length = 16
for item in [sample, divider, toggle] { bar.removeStatusItem(item) }
```

- [x] 为原型增加按钮 target/action 切换 divider.length，并提供退出菜单；为所有项目设置独立测试名称。编译运行：`swiftc /private/tmp/fastbudo-menu-bar-probe.swift -o /private/tmp/fastbudo-menu-bar-probe -framework AppKit`。保持用户手动将「测」放在分隔左侧、收纳按钮放在右侧，不发送模拟拖动事件。
- [ ] 验证「测」可消失/恢复、右侧按钮保持可用、恢复后仍可点击；正常退出无残留占位。用自己的原型进程验证异常终止后的布局恢复，不强杀 FastBudo 或 Finder。
- [ ] 分别记录刘海屏、空间不足、全屏、睡眠唤醒、重启和显示器切换的结果；没有条件的项目标为未验证。无法安全展开时停止正式接入，报告具体布局与结果，不能改用额外权限绕过。
- [ ] 将实测结论写入验证文档并加入索引；运行文档门禁，提交中文说明及 Codex 署名。临时原型标记为实验，不随应用发布。

## 任务二：实现收纳状态与生命周期

**接口：**新增 `@MainActor @Observable final class MenuBarController: NSObject`。构造 `init(defaults: UserDefaults = .standard)` 不创建状态栏项；使用 `enabled: Bool`、`collapseOnLaunch: Bool`、只读 `isCollapsed: Bool`，方法 `start()`、`toggle()`、`expand()`、`stop()`。偏好键为 `menuBarEnabled`、`menuBarCollapseOnLaunch`，均默认 false。`stop()` 释放项但不改偏好。

- [x] 先在 `AppTests/MenuBarTests.swift` 添加隔离测试；以下为默认状态、偏好恢复和禁用不切换的实际断言：

```swift
@MainActor @Test func disabledManagerDoesNotCollapse() {
    let name = "FastBudoTests.MenuBar.\(UUID().uuidString)"
    let defaults = UserDefaults(suiteName: name)!
    defer { defaults.removePersistentDomain(forName: name) }
    let manager = MenuBarController(defaults: defaults)
    defer { manager.stop() }
    #expect(!manager.enabled)
    #expect(!manager.collapseOnLaunch)
    manager.start()
    manager.toggle()
    #expect(!manager.isCollapsed)
    manager.collapseOnLaunch = true
    let restored = MenuBarController(defaults: defaults)
    #expect(restored.collapseOnLaunch)
    #expect(!restored.enabled)
}
```

- [x] 运行 `xcodegen generate` 和定向测试，确认失败指向新类型尚未实现：`xcodebuild test -scheme FastBudo -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/xcode -only-testing:FastBudoTests/MenuBarTests`。
- [x] 以任务一通过的状态栏项机制实现控制对象。强持有按钮和分隔项；创建和删除仅走同一处代码；使用 `@ObservationIgnored` 管理 defaults、NSStatusItem 引用及运行标记。按钮以 target/action 调用 toggle，保持项的稳定 autosaveName（先核对官方 API），不写其他应用的位置偏好。
- [x] 状态逻辑按以下顺序实现，不引入状态机框架：

```swift
func toggle() {
    guard enabled else { return }
    isCollapsed.toggle()
    updateLayout()
}
func expand() {
    isCollapsed = false
    updateLayout()
}
```

`updateLayout() -> Void` 是私有方法，应用任务一验证的长度及按钮图标、toolTip、辅助功能标签。`start()` 幂等：首次启动按偏好创建并应用收起；运行中 enabled 从 false 改 true 只创建并展开。禁用时展开并释放项目。`stop()` 展开后释放，重置运行标记；重复 stop 无副作用。控制对象不关闭第三方应用。

- [ ] 增加启用状态的测试：只在明确启动的隔离集成测试进程中创建测试状态栏项；用唯一 autosaveName 避免改动真实布局。验证 `start → start` 不重复、`toggle → expand` 恢复、`disable → enable` 展开、`stop → stop` 清理；保留 `NSStatusItem` 内部只读测试访问以断言实例身份与释放，勿为此引入通用工厂框架。真实项目布局不由自动测试更改。
- [x] 将控制对象注入 AppDelegate，保留原默认构造入口。`applicationDidFinishLaunching` 调用 start；`applicationWillTerminate` 调用 stop；不在 `applicationShouldTerminate` 或 `windowWillClose` 清理，确保任务阻止退出和关闭窗口时收纳继续工作。
- [ ] 定向测试通过后提交本任务；若测试需操作真实菜单栏，改为独立测试进程并明确人工运行，不隐式启用用户配置。
